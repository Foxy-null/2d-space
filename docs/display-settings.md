# 画面表示

状態：合意した仕様を実装済み。

ウィンドウを大きくすると、キャラクター、地形、文字、ボタンを一緒に拡大する。基準は1280×720で、ステージ内で一度に見える範囲と縦横比を保つ。縦横比が異なるウィンドウでは上下または左右に余白を付ける。

## Godotの埋め込み実行

F5・F6で起動したGame画面の右上にあるサイズ設定で「Keep Aspect Ratio」を選ぶ。Gameバーのある別ウィンドウも埋め込み実行に含まれる。既定の「Fixed Size」では、表示はプロジェクトで指定したサイズに固定される。

この選択はプロジェクトごとのエディター設定に保存され、`project.godot`には保存されない。新しい環境では、Godot側で一度選択する。[公式の操作説明](https://docs.godotengine.org/en/4.7/tutorials/editor/game_embedding.html#embedded-window-sizing)を参照する。

埋め込み実行中は、ゲーム側から全画面などのウィンドウモードへ切り替えられない。[公式ドキュメントの制約](https://docs.godotengine.org/en/4.7/tutorials/editor/game_embedding.html#limitations)に従い、ゲーム内の全画面ボタンは無効にし、Godot側の表示設定を使うよう案内する。ゲーム側の表示設定は読み書きしない。

## 単独実行と書き出し版

- F11、ステージ選択画面の全画面ボタン、共通ポーズメニューの全画面ボタンで切り替える。全画面中はボタン名を「ウィンドウ表示 [F11]」にする。
- キーボードとコントローラーで各ボタンへ移動できる。ポーズ中の切替では、プレイを停止したままフォーカスも維持する。
- 前回のウィンドウサイズと全画面状態を`user://display_settings.cfg`へ保存し、次回の単独起動時に復元する。
- 全画面に入る前のウィンドウサイズを保ち、解除時にそのサイズへ戻す。サイズの復元時は現在のモニター内に収める。
- リサイズ中の保存は最後の変更から0.3秒後、全画面切替とウィンドウを閉じる操作では直ちに行う。
- 不正な保存値は採用せず、保存できなかった場合もその起動中は表示の変更を適用する。

F11は画面操作の予約キーとする。以前の操作設定にF11の割り当てがある場合は、読み込み時にそのキーを除外する。その操作のキーボード・マウス割り当てがなくなる場合は、キーボードの初期配置を戻す。

## 実装と確認

`scripts/display_settings.gd`をAutoloadとして全画面切替と保存処理を共有する。`project.godot`の拡大設定は`canvas_items`、縦横比は`keep`とする。各ステージのカメラや地形のサイズは変更しない。

`tests/display_settings_test.gd`は、描画ありの独立ウィンドウで実行する。

```sh
godot --path . --max-fps 60 --script res://tests/display_settings_test.gd
```

リサイズによる表示倍率、見える範囲の維持、自動保存、全画面状態の再読み込み、元のサイズへの復帰、全7プレイ画面のポーズ中の切替、不正な保存値、操作できない環境での保存抑止を確認する。ヘッドレス実行では、表示操作と保存を行わないことだけを確認する。

Linuxでは別プロセスを起動し、実際の終了・再起動後の復元も確認する。この確認では、保存先を隔離してプレイヤーの設定を保護する。仮想画面を使う場合は、全画面切替を処理できるウィンドウマネージャーも起動する。

操作設定のテストでF11の予約と旧設定の読み込みを確認し、既存のステージ選択、共通ポーズメニュー、設定画面の移動とポーズのテストも実行する。

Godot 4.7.2のLinux環境で、表示機能56項目、ステージ選択144項目、共通ポーズ171項目、設定画面の移動43項目、設定画面とポーズの連携109項目、操作設定のテストが成功した。再起動の確認にはXvfbとOpenboxを使用した。表示機能は通常描画でも確認し、回帰テストは通常フレームの描画を止めて実行した。ステージ選択とポーズメニューは必要な画面を描画し、画像でも配置を確認した。Windows実機とエディター内の埋め込み画面は未確認。

自動ポーズの追加は今回の対象に含めない。
