# 回廊の運搬と複合ルート6室

[Issue #149](https://github.com/Foxy-null/2d-space/issues/149)。第19〜24室と任意の巻物2個を追加し、回廊を24室・7巻物にする。[合意](celeste-exploration-design.md)の、既習操作を組み合わせた短い課題、地形による必須化、元へ戻る任意枝を継承する。旧18室の原点・地形・巻物5IDと共有Player、相棒、Spring、反射、重力、靴、風の物理は変更しない。旧第18室のGoalだけを第24室へ移す。

実装前にはSpring→靴、靴→Spring、反射→靴、天井→Spring、風→保持壁キック、運搬物の選択という6種類を仮説にした。第24室の選択は、緑を再取得する枝ではなく、緑・赤のいずれかをそのままGoalへ運べる二経路として採用した。保持する実物と地形で攻略が変わり、操作履歴や収集数では出口を閉じない。緑で右のSpring経路を使う代替も許し、色ごとに道を排他的にはしない。上側の靴は左の攻略例に使い、最初の共通560pxの靴課題は両経路に残す。

新室は各室の実幅・高さで境界とカメラを求める。入口と低い台では上寄り、上層では通常の高さへ追従し、下降の速度も用いて主人公と保持物が画面に収まるよう調整する。新室だけ右端に40pxの視野を残す。第22室は反転中に相棒が主人公の下へ来るため、その全高を確保する。新室のHUD幅は436px。第20室はSpringのある最初の台の帯でだけ左下へ移し、巻物が見える上層では右下へ戻す。第24室は最初の台の高さを越えてから左側のY190へ移し、Spring・赤傘・任意ヒントを隠さない。第23室は風からの着地を隠さず、ポーズボタンとも重ならない左上へ置く。旧18室のカメラとHUD位置は維持する。

## 二つの任意枝

第20室の `companion/spring_left_06` は主経路の上棚から左上へ離れた (140,620)。幅190のY700棚で確定し、同じY890の上棚へ戻って出口へ進める。第23室の `companion/upper_wall_07` は保持壁キックで登った後の左上 (1030,510)。幅200のY600棚で確定し、左壁の頂上から右の主経路へ戻る。入口には既存の小さい巻物印だけを置き、常設説明は増やさない。両枝は相棒を保持して往復でき、通常の本編では巻物に触れない。

未確定はR・実際の落下・途中帰還で元へ戻り、StaticBody2Dへの安全な着地で確定した分はR・死亡・再訪・途中帰還後も残る。共通の保存処理と既存IDを保ち、選択の分母を実配置7個へ揃える。テスト保存先はPID付きの専用ファイルで、別プロセスへそのパスを明示して再読込する。

## 実入力による調整

- 第20・24室の最初の台は左端を600から540へ延ばした。弱入力16fでは中心が585pxで、端に片足だけが掛かっていたため。幅600の安定した休憩台にした。
- 第21室の反射は半径64、中心(248,1962)。最初の着地先と反射全体が入口から見える高さとカメラにした。台へ置き換えたり、共通の反射性能を変えたりしていない。
- 第22室のSpringは(480,1100)。元の左寄り配置では上Dashが最初の天井の角へ当たり、正規経路の高度を失った。Downを天井の左側へ、Springを床の右側へ分け、次の台へ向かう前に屋根を抜ける。
- 描画では第23室のHUDとポーズボタン、第20・24室のHUDとSpring・赤傘が重なった。HUDを幅436へ狭めた。第20室は1000<Y<1540の最初の台で左下、上層は右下へ置き、実巻物・控えめな印・棚から見た帰りの台を隠さない。第24室は最初の台の高さを越えた後に左Y190へ置く。初案のY160では任意ヒントのY155〜184と24px重なったため、30px下げて6pxの間隔を確保した。R直後の1frameも再現したため、復帰時にカメラと一緒にHUDを同期する。第24室の赤傘は入口からポーズに隠れないX950へ寄せた。
- 第24室の赤経路は、初案では風に一度も入らずGoalへ運べた。実接触を検査し、風を(1810,820)・400×260へ寄せた。赤を選ぶ台から次のY860の着地先が見え、Spring後はそこで3秒休める。通常・弱入力の全6例で実際に風へ入る。

## 検証

Godot 4.7.2、物理更新60Hz・固定描画60fps。`Input.action_press` の水平強度1.0と0.8を使い、JoypadMotionのdeadzone補正とは区別する。16・20・24fは離散的な入力間隔であり、その間の全時機を保証するものではない。表の時間は検査用の減速待ち20fと静止180f、計3.33秒を含む。赤経路は最初の台とSpring後の2回で計6.67秒を含む。これらは操作の量や10〜20秒の目安へは算入しない。通常20fの第21・23室の操作は各約8.38・8.08秒と目安より短く、反射→靴、風→保持壁キックの2課題と30秒の再試行上限を保つ。人の初見所要時間は未計測。

`corridor_fourth_route_test.gd` は両strength×16/20/24fの6profileで6室連続攻略、7つの実巻物ID、24室と唯一の最終Goal、主経路の巻物未取得、保持した3秒静止、実36×52の主人公と保持物の全矩形がviewport内・HUD外であることを毎物理frameで確認する。4profileの64,075項目に通常16f・24fの15,751・16,267項目を加え、計96,093項目。HUDの最終調整後、第24室の緑6profileを任意ヒント付きで25,224項目確認した。`corridor_fourth_choice_test.gd` は同じく任意ヒントを表示した赤経路6profile、実持ち替え、実風接触、赤でのGoal到達と緑の追加Jump未使用を確認し、30,611項目が成功した。緑保持で右Springから実Goalへ運ぶ追加例は上側の靴を使わず、正当な代替経路を操作履歴で閉じないことも確認する。

独立した比較では第24室のヒント表示を有効にし、緑・赤の各6profile、計12経路・157,168項目を確認した。主人公と保持物がInfo・Hint・Pause・表示中のクリアカードに重ならず、選択時の両物体と次の足場が見える。既存のテストには、ヒントとInfoが毎物理frameで重ならない最小の回帰を残した。

`corridor_fourth_required_test.gd` はSpring・靴・反射・Up・風・保持追加Jump・壁キックを個別に省き、8方向Dashと3時機など490経路を比較した。相棒を移動して実支持からGrabと通常Jumpを同時に行う第20・24室、Springへ落ち直す第19室、反転からDownを省く第22室、実Down後のSpringから屋根角を蹴る48例を含む。追加で第23室の相棒を実際に160pxへ移し、背上から踏み切る24経路も比較した。合計514例、1,618＋120項目で対象の足場・出口へ届かなかった。操作を無効化する比較は、共通物理を変えずテスト内だけで行う。

`corridor_fourth_retry_test.gd` は17,712項目で全新室のR・実左トゲ接触・資源と実物位置の復元・その後の実出口到達を確認した。旧第18→19室と新第23→24室の実移動で、前室の相棒がリセットされ、新室の運搬条件を満たさないことを比較する。Spring発射中のR後の再発射、赤傘を選んだ後のR・実接触死・両物体の復元・赤の再取得とGoalも含む。

巻物は通常・実axis0.8で31,610項目を確認し、第20室の往復は13.43/14.03秒、第23室は14.58/15.07秒。実巻物と小さい入口印が上棚から見えることも検査する。別プロセスの5項目で保存した両IDと「2 / 7」の選択表示・アクセシビリティ名、薄い再訪表示を確認した。第23室の上投げ・手ぶら登り・再取得は12経路43項目で、実上登りを含む全例で保持壁キックの代わりにならなかった。

全24室は `stage_4_test.gd` の992項目で実Goalまで通過し、空手の全出口拒否・天井・移動トゲ・復帰・メニュー・再入場を含めて成功した。旧第10〜15室・最初の3巻物・再開257項目と別プロセス5項目、旧第16〜18室の4profile・残り2巻物8,173項目と別プロセス5項目も成功した。新旧7IDの保存経路と分母7の表示を保つ。最新main統合後の短い共通回帰は、クリア画面71・選択144・到着後再試行32・巻物の部屋移動48項目が成功した。元の保存先を使う既存試験は、PID付き保存先を設定する一時的な継承fixtureで実行した。

最終描画は通常20fの実入力で25,361項目、ヒント表示を描画へ反映する1frameを待った赤経路の追加撮影2,836項目が成功した。[32枚のPNG](screenshots/corridor-fourth/)を目視し、[第20室の巻物と印](screenshots/corridor-fourth/room20_upper.png)、[同じ棚への帰還](screenshots/corridor-fourth/room20_scroll_return.png)、[第23室の上枝](screenshots/corridor-fourth/room23_upper.png)、[赤傘への持ち替えとヒント](screenshots/corridor-fourth/room24_red_hint.png)、[赤での実Goal](screenshots/corridor-fourth/room24_red_goal.png)、[選択の2/7と他ステージの最新分母](screenshots/corridor-fourth/room23_selection.png)を確認した。描画環境のV-Sync非対応警告があり、一部のテスト終了時にはObjectDBが2個残る警告が出た。実行中のスクリプトエラーはなく、各fixtureは成功終了した。
