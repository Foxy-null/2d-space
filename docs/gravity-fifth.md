# 重力第26〜31室：上り方と帰り方を変える六連携（Issue157）

[Issue157](https://github.com/Foxy-null/2d-space/issues/157)。既存25室の原点・地形・8巻物IDと共有Player／ギミック物理を保ち、native6室と任意2枝を追加する。最終Goalは31室へ移す。チュートリアルの必須16＋任意17室には変更しない。

寸法・踏切・帰路は仮説であり、実入力を測って変更する。同じ二室を横へ複製して数だけ増やさず、壁、水平回復、風、反発、追加Jump、左への合流を異なる入口・静止面・落下先へ組み合わせる。各checkpointから休憩込み最大30秒、静止面では3秒休んだ後にも再出発できることを検査する。無駄な平地や強制待機で時間を延ばさない。

新2枝の入口は既存の小さな巻物印だけを使い、主経路では未取得とする。仮取得のR・実接触死・離脱、確定後の同じ操作、自然帰還・到着後の再訪、実保存の別process・選択表示とアクセシブル名を検査する。ユーザー保存から独立したPID付きfixtureを使う。

旧25室を最終とするdriver・回帰・仕様を検索し、新26室への実境界へ改める。旧25室の傘camera／HUD、既存8枝、全31室と左右往復も確認する。新室は通常／実axis0.8×16／20／24f、ヒントONを含む全frameの実体／保持物とviewport／HUD、次の安全面をnative PNGで確認する。

未着地・parse error・途中終了を成功件数へ含めない。本編9〜15分・巻物込み15〜24分は未達／人による初見所要時間は未測定のまま扱う。

## 調整中に検出した経路と試験の区別

第27室の初稿ではCrystalを外した実入力が左天井のlocal（1216.25,626.07）へ着地し、以後はDownからGoalへ進めた。左天井の右端を80px左へ寄せる案は弱入力の着地を損ねたため採用せず、天井の幅を保って水平回復の高さより下にトゲ面を置く。到着後は既存の`return_retract`で帰路を開く。操作履歴による制限は加えない。

水平Crystalの比較では、Dash終了と`body_entered`の通知に1tickの差がある。正例driverはDashの終了と実収集signalの両方を待ち、通知前の判定失敗を成功へ含めない。省略比較では、実死による通常重力への復帰をDown通過と誤認しないよう、各実入力frameの死亡前に着地／重力を観測する。専用checkpoint fixtureからの攻略と、旧第25室から続けた攻略は分けて記録する。

第31室では、傘を保持した左Dash1回でも回復を省いて左天井へ着地できた。浮上中の実軌跡を観測し、隙間に吊り壁と下向きのトゲを置き、深い斜めDashには下のトゲ面を置く。正規の2回水平Dashが通る中間の高さは残す。保持物を地形で止めるという推測や、使用履歴のロックには頼らない。

最終の遅い32f踏切では、第27室の単発左Dashが低いトゲ面より上を通り、左天井の右縁（local1232,626）へ着地した。正規の弱16fは（1222,704）から（1184,638）を通って内側へ着くため、天井幅を削らず右縁（1224,585）に半長25pxの右向きトゲを加えた。半長35pxの初稿では弱16fを損ねたため上へ寄せて短くし、正規連携の低い通過面を広げる。これは到着後には撤去する。初稿の失敗batchや診断probeは合格件数に含めない。

第28室の巻物床の左端には右向きの短いトゲを常設し、風へ戻る右側の安全面を残す。床の幅200pxに対して右向きのトゲ先端はX156、通常の休憩中心X240から84px離れている（縦の半長35pxと横の突出16pxを区別する）。主人公の半幅18pxを足した中心の接触境界X174までは66pxの余裕がある。到着後も実際に触れて死ねること、確定済み巻物が残ること、通常／実axis0.8で右の風へ戻れることを同じ地形で確認する。

第31室だけ`camera_offset_x=-256`を指定して左の経路を広く映す。旧25室を含む他室は既定値0のまま。右の反転天井で3秒休むphaseでは、次のDown矢印の全体と左天井の幅240px超がviewport内にあることを実矩形で検査する。最後の右帰路は実投げした傘が通路に残る場合も実Grabで拾い直し、右境界へ保持物を押し付けない位置で止まる。

## 実行条件と結果

Godot 4.7.2 Linux arm64、`--fixed-fps 60`。全実行を共有2枠のwrapper経由で行い、1担当1job・ジョブ間2秒を守る。保存は`user://gravity_fifth_*_<PID>.cfg`等の専用ファイルを使い、既存ユーザー保存に書かない。横入力は`Input.action_press`の強度1.0／0.8を直接指定し、`Input.get_axis`の実値を検査する。ゲームパッドのデッドゾーンを通した0.8とは区別する。

新2巻物の全lifecycleは156,660項目で終了0。実仮取得のR／実トゲ死／選択への離脱、静止面での確定、3秒休憩、自然帰還と本線Goal、実到着後の探索、確定後のR／実トゲ死／再訪、PID保存の読み直し、見える個数とaccessible名を通常・実axis0.8で確認した。保存した新2IDを別プロセスで読み直す試験は17項目で終了0。その後の10/10表示は、旧8IDを明示的に加える個数互換fixtureであり、全10本を同一プレイで実取得したという主張ではない。旧8枝の実取得は各既存suiteで別に確認する。

新枝の計測は3秒休憩込み。到着前／到着後の順で、第28室は通常14.30／21.85秒、実axis0.8で15.10／24.57秒。第30室は通常13.05／19.15秒、実axis0.8で13.93／21.47秒。到着後の値には出口から枝の入口へ戻る接近も含む。最大でも30秒以内で、到着後にRや部屋の入り直しを要求しない。

描画は新6室の通常20fが29,452項目、巻物の通常短縮captureが52,748項目、第31室の最終横camera再撮影が8,418項目でそれぞれ終了0。撮影時の2frame待機は時間へ含まれるため、踏切matrixの値とは分ける。render環境のVSync変更非対応警告は出る。調整中の個別試験では終了時ObjectDB2件も観測したため、終了コードだけで成否を決めず、明示した完了印とSCRIPT ERRORの有無を確認する。

縁トゲの初稿候補で、ギミック省略・代用比較は230経路・31,261項目で終了0、実行エラー・終了警告なし。ただし続く正例で弱16fが接触したため、この候補を最終実績とは扱わず、短く上げたトゲで両立を再検証する。内訳は第30室の高い回復48／Boots8、傘または風32、実傘の支持から同時Grab・Jump＋8方向Dash16、第27・31室の水平回復なし48（16/24/32f）、第31室で実傘を保持した回復なし8、反転Springなし24、壁キックなし16、入口から上／斜めの外回り30。制御比較では該当Crystal／傘を削除、風加速度0、Springのcollision mask0を使うが、途中の位置・速度・移動資源は注入しない。実支持に失敗したfixtureは省略防止の成功に数えない。全入力列の不可能証明ではない。

短く上げた最終の縁トゲ・横cameraと最新版の他ステージを合わせ、通常／実axis0.8×16/20/24fの全36経路は181,378項目で終了0、実行エラー・終了警告なし。主人公の全実体と保持傘は各physics frameでviewport内かつ表示中のInfo／Pause／Status／ClearCardと非交差。主経路では新旧の巻物10本を取らない。

各値には静止面ごとの3秒休憩、実到着台、左向き室の右への自然帰路を含む。第28・31室は10〜20秒の目安を超えるが最大30秒以内。自動化した既知経路の時間であり、人による初見の本編9〜15分／巻物込み15〜24分は未達・未測定。実機、60fps以外、全入力列、音声ObjectDBの長時間蓄積は確認していない。

連続した左戻りでは、第30室のReturn2232がGoal2200の実Base（X2130〜2270）と重なり、いったん第30室へ移った後に第31室へ押し戻される不具合を検出した。右Goalが同じ配置の新26・28・30室だけReturnを2090へ移した。主人公の右端2108とBase左端2130の間に22px残り、他の部屋の地形・元8ID・共有物理は変更しない。回帰には全新Returnと実Goal三部品の非交差、左転送後25f静止・操作復帰・正しい室の保持・Rを追加した。`respawned`には正常な部屋転送も含まれるため、左右の転送と実接触死は区別し、左の1回転送ではsignal増分が正確に1であることを検査する。

Return位置の修正後、R／実トゲ死／再攻略と実旧25→31連続移動・全6箇所の左戻りは45,285項目で終了0、実行エラー・終了警告なし。左移動の正常転送は各1回のみで、次室へ跳ね戻らず、Rは前室の現物Returnを使う。専用checkpointでの6室再攻略と、旧25から続けた7室は別の区間として同じsuite内で観測した。

縁トゲを短く上げた後、影響する水平回復なし48経路（2,802項目）と入口の上下外回り30経路（4,893項目）を再実行し、どちらも終了0・実行エラー・終了警告なし。特に第27室の32f左Dashも実接触死となり、同じ最終地形で正規の弱16f成功と両立した。残る152比較の対象となるギミック判定・移動経路は不変で、同じSpawnからの比較を先の230比較で確認済み。重複実行の項目数を単純合算しない。

追加の実Superdash18例は993項目で終了0・実行エラー・終了警告なし。第27室素手、第31室素手／実傘保持の3状態から、地上Dash→Jumpを0/4/8fで実発動し、16/24f後に本当にDashが残っていれば左Dashも使わせた。全例で実`superdash` actionを必須にし、単なる通常Jumpや未発動を代用防止の成功へ数えない。現物の左天井／Down／Goalへは到達せず実トゲ死となる。`--only=super`で単独再実行でき、一括requiredには計248代表を含める。
