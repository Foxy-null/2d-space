# Celesteを参考にした既存ステージの改善

2026-10-23調査開始。同日、Q1〜Q4の推奨案にユーザーが合意し、改善ループを開始した。

## 確定している条件

- 対象は既存ステージ。部屋は縦横どちらにも拡張できるが、失敗後のやり直しを長くしない。
- 各課題で扱う操作・ギミックは、使用履歴による出口の判定だけでなく、配置によって攻略に必要にする。
- 不要な常設ラベルや説明を減らし、地形、危険箇所、安全な足場、ギミックの位置から進み方を伝える。
- 必要な新ギミックは追加できる。トゲは既存実装を調べて再利用を優先する。
- Q1：難易度は段階的にする。未経験者が序盤で操作を学び、後半で組み合わせと歯ごたえを増す。ユーザー回答で確定。
- 方針の合意後、`/goal`に相当する継続目標を使い、タスク作成→テスト→PR作成→PRレビュー→マージを繰り返す。
- Weekly残量が5%未満、または大幅な増加によって100%近辺に戻るリセットを検知したら、新規タスク作成を停止する。進行中タスクの終了を確認してから、この環境のCodexのfastモードをオフにする。
- コミット、PRのタイトルと説明は日本語で書く。

## 調査で確認したこと

### Celesteの資料

1. [開発者Maddy Thorsonの「Celeste & Forgiveness」](https://www.maddymakesgames.com/articles/celeste_and_forgiveness/index.html)では、崖を離れた直後のジャンプ猶予、着地前の入力予約、壁ジャンプの位置猶予、角での補正などを説明している。入力や位置に少しの余裕を設け、意図した動作を成功させやすくする設計である。今回も、必須操作を設けることと、入力を極端に厳しくすることを混同しない。
2. [開発元のCeleste製品ページ](https://maddymakesgamesinc.itch.io/celeste)は、ジャンプ・空中ダッシュ・登りという少数の操作の深さと、失敗からすぐ再挑戦できることを特徴としている。今回の改善も、仕掛けの数を増やす前に既存操作の使いどころと復帰の短さを見直す。
3. [GDCワークショップの登壇者インタビュー](https://www.gamedeveloper.com/design/gdc-2017-level-design-workshop)は、Celesteの講演が地形による暗黙の学習、速度を追求するプレイヤー、報酬の配置を扱うことを説明している。今回の「地形で語る」方針との接点になる。
4. [開発チームのAMA](https://www.reddit.com/r/NintendoSwitch/comments/7tuubc/hey_were_the_dev_team_behind_celeste_ask_us/)では、操作が難しい部屋は解法を理解しやすくし、探索・パズル・精密操作という異なる難しさをペース配分に使う、という回答がある。現在は回答者名が削除されているため、特定の開発者名には帰属させない。本作では、精密操作を要求する場面ほど次の着地点と必要な仕掛けを見やすくする。
5. [GDC講演「Level Design Workshop: Designing Celeste」](https://gdcvault.com/play/1024307/Level-Design-Workshop-Designing-Celeste)と[公式公開動画](https://www.youtube.com/watch?v=4RlpMhBKNr0)も特定した。ただし取得時にVaultのメンテナンス表示と動画本文の取得制限があり、講演の内容全体は確認できていない。以下の配置案を、未確認の講演内容やCelesteの公称基準として扱わない。

上記を踏まえた本作への提案は、「安全に効果を見る→同じ操作で短い課題を越える→既知の操作と組み合わせる」という流れにすること。必要な操作を絞っても、踏み切り位置や入力時機には幅を残す。これは本作向けの設計案であり、Celesteの全ステージの分析結果ではない。

### 既存ゲーム

以下は調査開始時点の構成と課題。改善後の仕様・確認結果は各ステージの文書とREADMEに記録する。

| ステージ | 調査開始時の構成 | 確認した課題 |
| --- | --- | --- |
| 1：チュートリアル | 17部屋 | 一部の部屋は高度な代替操作で出口側へ着けるが、ミッション履歴のロックで完了を防いでいる。地形による必須化との違いを整理する必要がある。 |
| 2：星のぼりの塔 | 6区間、24段 | 各区間のバネ・クリスタル・生物を使わず、ジャンプと壁登りだけでも登頂できる経路が仕様・テストで保証されている。 |
| 3：壁キックと重力 | 6部屋 | 操作履歴ロックを使わず、到着によってクリアする。3・4部屋目には重力による迂回を防ぐテストもあり、地形による課題の既存例になる。 |
| 4：星渡りの回廊 | 6部屋 | 全出口で相棒の保持が条件。成功経路は追加ジャンプを使うが、使わない経路の検証は不足している。全室に天井トゲ、計22個の巡回トゲがある。 |
| 5：暴風バンパー峡谷 | 12部屋 | 43個のバンパーと風を使い、番号順の反射が出口条件。部屋内の休憩足場がなく、連続操作に負荷が寄っている。 |

根拠：`scripts/stage_select.gd`、`scripts/tutorial.gd`、`scripts/stage_2.gd`、`scripts/stage_3.gd`、`scripts/stage_4.gd`、`scripts/stage_4_room.gd`、`scripts/stage_5.gd`、`scripts/spike_block.gd`。

特に塔の迂回は[現行仕様](stage-2.md)にも記載があり、`tests/stage_2_test.gd`が成功を確認している。チュートリアルの代替到達も`tests/tutorial_extra_jump_route_test.gd`、`tests/tutorial_companion_route_test.gd`、`tests/tutorial_combo_jump_test.gd`、`tests/tutorial_final_glide_test.gd`が保護している。改善時には、これらを無関係な回帰として残さず、合意した必須操作に沿って期待値を更新する。

復帰は既に即時で、チュートリアルとステージ3〜5は部屋入口へ、塔は到達済みの復帰足場へ戻る。塔の復帰地点は足場への着地で更新する。既存のコヨーテタイムと先行入力受付は各0.14秒あり、まずは移動性能を保って配置を調整できる。

部屋の拡張は、地形だけでは完了しない。現状は1280×720を基準にカメラ、出口、落下境界、復帰位置、テストの座標が決まっている。トゲもステージ4の進行管理と天井幅1280に依存する。他ステージで使う場合には、既存の接触判定と復帰処理を保ったまま、その依存を解く必要がある。

## 設計の決定木

```text
既存ステージの改善
├─ 対象プレイヤー
│  └─ Q1：段階的な難易度【確定】
├─ 地形で操作・ギミックを必須にする【確定】
│  └─ Q2：地形で必須にできた部屋の不要な使用履歴ロックを外す【確定】
├─ 再挑戦を短くする【確定】
│  └─ Q3：導入5〜10秒、通常10〜20秒、原則30秒以内【確定】
├─ 既存ステージを改善する【確定】
│  └─ Q4：5ステージのテーマを保ち、部屋の再構成を許可【確定】
└─ 合意後に改善ループを開始する【確定】
   └─ 7日枠の残量を定期取得し、停止条件の成立後に終了処理する
```

### 合意した方針

- Q2：地形で必須にできた部屋から使用履歴の出口ロックを外す。重量スイッチや運搬先など、ゲーム内の意味がある条件は残す。
- Q3：迷わず成功した場合、導入5〜10秒、通常10〜20秒、後半の連続課題でも原則30秒以内。超える場合は途中に復帰地点を設ける。Celesteの公称値ではなく、本作向けの目安。
- Q4：既存5ステージのテーマと基本操作を保ち、必要なら部屋の順序・数・区切りも変える。新ギミックは既存の仕掛けでは狙った体験を作れない場合に追加する。

## 改善ループ

最初は塔の必須ギミック化か、チュートリアルの1課題を対象に、配置・復帰・攻略確認・迂回確認を一組として改善する。テストを通った配置は描画して、次の足場、危険箇所、必要なギミック、着地点が見えるか確認する。人による遊びやすさの評価と、自動入力での通過確認は区別して記録する。

1タスクごとに変更前の問題、必要な操作、許容する別経路、復帰地点、変更後の成功経路を残す。正規ルートの成功だけでなく、狙った操作を使わない典型的な迂回が通れないこと、落下・トゲ接触・手動再開で安全に復帰できることを確認する。

PRレビューでは攻略経路、復帰状態、文字による誘導の必要性、入力猶予、影響する既存テストを確認し、指摘を修正してからマージする。次のタスクは未解決の設計課題から選ぶ。別ステージの配置変更は並行できるが、共通の移動・トゲ・復帰処理の変更は競合を避ける。
