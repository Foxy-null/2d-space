# 峡谷の終盤と巻物ルート

[Issue #124](https://github.com/Foxy-null/2d-space/issues/124)。既存12室の後ろへ3室を追加し、全15室・57個のバンパーとする。旧最終到着台を第15室へ移す。主経路は巻物を取らずにクリアでき、反射履歴による出口ロックは追加しない。プレイヤーやバンパーの共通物理も維持する。

| 追加室 | 配置と操作 | 安全に止まれる場所 |
| --- | --- | --- |
| 第13室・折り返す空と巻物 | 右上の反射から左の低い反射へ戻り、右の切れ目を抜ける。2個目からさらに左上へ寄れば巻物を取り、3個目から主経路へ戻れる。 | 入口と、切れ目の前の幅120pxの片面足場。巻物はここで確定できる。 |
| 第14室・縦に抜ける峡谷 | 高さ1280px。下の入口から反射で上がり、左への折り返しを経て右上の出口へ進む。 | 入口と、上昇の途中にある幅160pxの片面足場。カメラは縦に追従する。 |
| 第15室・嵐の帰り道 | 横風から下向きの風へ進み、右の反射から一度左へ戻って最後の反射を狙う。 | 入口と最終到着台。6個の反射をつなぐ成功経路を30秒以内に収める。 |

巻物IDは`canyon/turning_sky_01`。2個目の反射の左上に控えめな巻物印を置き、目的地の巻物自体も入口の安全な足場から見える。追加の説明ラベルは置かない。新しい足場を収集用の上層へ置かず、反射なしで主経路を省略する踏み台を増やさない。

巻物に触れたら追従し、安全な休憩台に0.2秒着地すると獲得を確定する。確定前のR・死亡・途中帰還は保存せず、確定後のR・死亡・未クリアの途中帰還では保存を保つ。選択画面の配置総数は1個。別の部屋へ通常移動するときの未確定巻物の持ち越しも共通処理を使う。

`scenes/canyon_room_13.tscn`〜`canyon_room_15.tscn`は、既存の地形描画・バンパー・風・到着台・巻物を組み合わせたGodotの編集可能なシーン。各部屋の入口で復帰地点を更新する。高さのある部屋では部屋のメタデータからカメラと場外復帰の下端を決め、固定画面の既存12室は従来の範囲を使う。

検証は、ステージ選択から全15室を通過する`tests/stage_5_test.gd`、追加3室と巻物の`tests/canyon_expansion_route_test.gd`、全室で反射を無効にする`tests/canyon_required_bumper_test.gd`を使う。後者は通常ジャンプと8方向Dashなど2430入力例と、第9室の岩壁からの45例を扱う。有限の典型入力の比較であり、任意の入力列に対する不可能証明ではない。

2026-10-25、Godot 4.7.2 / Linuxで確認した。全15室の連続攻略は5956項目、反射なし比較は2536項目、追加室と巻物は43項目が成功した。追加室の成功時間は次のとおり。横入力0.8はソフトウェアの入力強度で、実機パッドの校正結果ではない。

| 部屋 | 通常横入力 | 横入力0.8 |
| --- | --- | --- |
| 第13室 | 6.38秒 | 6.40秒 |
| 第14室 | 5.18秒 | 6.90秒 |
| 第15室 | 9.23秒 | 8.60秒 |

通常の攻略では巻物を拾わず、任意ルートを選べば約5.70秒で取得から主経路の休憩まで到達した。横入力0.8でも往復と確定を確認した。休憩台で3秒間入力せず停止でき、確定後の実落下、R、途中帰還、選択画面の`1 / 1`表示、再読込も成功。初期配置では弱入力で帰りの反射に間に合わなかったため、巻物を帰路側へ40px動かし、主経路では取らないことも再確認した。

出口の単独比較87項目、既存入口168項目、全ステージのクリア表示71項目、到着台の再挑戦32項目、通常部屋移動48項目も成功。薄い片面足場を使う出口の単独fixtureは、固定の中心座標ではなく実際の衝突形状の上端から着地位置を決める。

Xvfb / Mesaの描画では追加3室を通常入力・0.8入力で通過し、巻物の最終配置も描画付きの21項目で確認した。縦カメラの上層も別の成功入力で撮影した。

独立レビューでも追加43項目・全15室5956項目・出口87項目が通過した。追加の実入力8項目では、第14室の中間休憩に着地して3秒止まり、ジャンプと上Dashから2個目の反射へ戻り、3・4個目へつないで死亡せず出口へ到達した。Rと下端落下による下層の復帰地点・カメラも確認した。
