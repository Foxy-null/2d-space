# ステージ4：星渡りの回廊

全6面で、入口にいる緑の生物（Jump Creature）を持ったまま出口まで運ぶ。持っている間は壁登り・壁掴みができず、壁キックと生物の追加空中ジャンプを使って進む。追加ジャンプは足場への着地で回復する。既存のプレイヤーの性能は変更していない。

各面は1280×720の固定画面。出口の右端に生物を保持して着地すると次へ移動する。最終面は生物を保持して到着台を踏むとクリア。生物を置いたり投げたりして出口へ届けるだけでは通過できない。出口には枠に入った相棒の絵を置き、保持中は下の丸印がチェック印へ変わる。相棒の近くにいるときだけ掴むキーを表示する。常設の長い操作説明は省き、詳しいヒントはポーズメニューから開く。

| 面 | テーマ | 地形と攻略の違い |
| --- | --- | --- |
| 1 | 相棒と高い足場へ | 入口から380px上の幅450pxの片面足場へ、追加ジャンプとDashを組み合わせて上がる。着地して休み、先の低い足場へ下る |
| 2 | 壁キックの峡谷 | 入口の縦穴を左右の壁キックで上がり、高い縦壁と低い足場を渡る |
| 3 | 低い天井の回廊 | 屋根の下にある低い足場を進む。追加ジャンプの早出しによる頭の衝突に注意 |
| 4 | 峠を越えて下る | 前半は高低差のある登り、後半は下りの着地位置を調整 |
| 5 | 離れ小島の大跳躍 | 小さな島の間の広い隙間を、横移動と追加ジャンプで越える |
| 6 | 折り返しの頂 | 右へ上がり、左上の足場へ折り返してから右へ大きく渡る経路 |

天井には全幅1280pxにわたる赤いトゲを配置した。上端0〜32pxに危険を表示し、画面内で接触して復帰する。HUDは天井トゲを隠さない位置へ下げた。動くトゲの往復範囲は点線で表示する。接触判定は移動区間を調べ、ダッシュによるすり抜けも防ぐ。

動くトゲは合計22個（従来11個の2倍）。面1に2個、面2〜6に各4個を配置する。高い足場への踏み切り、峡谷後半、低い屋根の横移動、峠の下り、島への踏み切りと着地、折り返し後の渡りに関門を追加した。天井のトゲはこの個数に含めない。各トゲの移動範囲が実際の通過経路を横切ることもテストで確認する。

落下・トゲへの接触・R / Startで現在の入口へ戻り、生物・トゲ・能力を初期化する。部屋移動で復帰地点を更新する。進行はプレイ中のみ保持する。

Esc・Back／Selectまたは「ポーズ [Esc]」で共通メニューを開くと、背景を含むゲーム全体が停止する。操作ヒントは部屋ごとに異なり、切り替えてもポーズを維持する。チェックポイントからのやり直し後も表示設定を保つ。ステージ選択への帰還には確認画面を出し、Esc・Back／Selectでは確認からポーズ、ポーズからゲームへ戻る。詳しくは [ポーズメニュー](pause-menu.md) を参照。最終到着台の大型吹き出しは隠し、足場とトゲを見えるようにしている。

配置は `scripts/stage_4_room.gd`、進行は `scripts/stage_4.gd`、トゲの移動・天井判定は `scripts/spike_block.gd`。

## 確認

```powershell
Godot_v4.7.2-stable_win64_console.exe --headless --fixed-fps 60 --path . --script tests/stage_4_test.gd
```

成功時は `STAGE_4_TEST_OK`。全6面を生物の保持・実入力・壁登りなしで通過し、生物の追加ジャンプを各面で使用する。第1室は追加ジャンプとDashを組み合わせ、第2〜6室はDashなしで攻略する。全出口の手ぶら通過拒否、各面の天井への上向きダッシュによる接触復帰（左・中央・右）、移動トゲ、落下、再開、クリア、メニューを確認する。`-- --screenshots`で画面を保存、`-- --search`で入口の待ち時間を探索する。

`tests/corridor_companion_route_test.gd`は、第1室を異なる4つの開始時機で約5.47秒で通過し、追加ジャンプとDashを使うことを確認する。巡回トゲを停止し、相棒の追加ジャンプを利用できなくした216通りの踏み切り位置・Dash方向・時機・壁キックでも、高い足場と出口に届かないことを検証する。危険物による失敗と、足場の高さによる必須性を区別している。

画像は`docs/screenshots/celeste-corridor-room1-entry.png`と`celeste-corridor-room1-rest.png`。入口から上段と次の着地先が見え、上段の相棒がHUDに隠れないことを確認した。

人による操作感の評価は未実施。
